## Compatibility and migration

Generated `Skill.copy$default`, `LoadSkillResult.copy$default` and the generated
`LoadSkillResult` serialisation constructor change. Existing explicit
three-argument constructors and copy methods remain callable. Consumers must
recompile against the new API. Nullable `OpenAIContainerFileResource.bytes`
changes the constructor, getter, component, copy and generated serialisation
signatures from primitive `long` to boxed `Long`. Consumers must recompile and
handle an absent byte count.

Old host skill-source and discovery entrypoints remain callable but reject
loading before I/O without explicit trusted-immutable attestation. A caller must
establish operator-controlled immutable roots, ancestor resolution and contents
throughout discovery. The declaration is not runtime proof of that precondition;
a false declaration permits hostile replacement and blocking I/O. Immutable
memory sources remain usable without filesystem attestation.

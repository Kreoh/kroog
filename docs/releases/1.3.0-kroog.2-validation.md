## JVM tests and compatibility

A clean source archive with the exact committed implementation inputs passed all 28
module-specific JVM suites: 2,665 tests passed, 57 existing tests were skipped, and no
failures or errors occurred. This covers core agents, extensions, memory, tracing,
event handlers, testing utilities, MCP, embeddings, vector retrieval, prompt models,
schemas, all affected provider clients, neighbouring streaming adapters, caches and
both Spring AI integrations.

Regression tests failed against the original implementations. Additional independent
review regressions caught and resolved inherited MCP array and object shapes and
incorrect embedding result counts. All 17 new history and lifecycle tests passed after
14 baseline failures. Existing incomplete streaming fixtures now emit genuine complete
messages and end metadata.

Affected module JVM JAR and POM tasks passed. Changed-source lint passed; unrelated
existing formatting violations were preserved. Compiled JVM ABI comparisons retain old
signatures. Updated JVM dumps represent additive cache, memory and embedding APIs;
Android and KLIB dumps remain untouched. Existing dump drift was not regenerated.

Unchanged cache consumer bytecode compiled against the preceding JARs runs against the
new JARs. It exercises the file-cache default-argument and explicit constructors,
in-memory constructor, Kotlin and Java Redis duration constructors, and cache-key
property. An old Java embedding implementer uses the new sequential batch default
without recompilation. Custom and Anthropic cache directives round-trip with their
concrete types, distinct TTL keys and explicit errors for missing registrations.

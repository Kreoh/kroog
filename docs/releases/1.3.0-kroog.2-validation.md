## Stream regression and JVM API baseline

The unchanged release failed the empty-only builder and Anthropic fixture
regressions at `StreamFrameExt.toMessageResponse:257`. With the native fix,
prompt-model passed 294 tests with three existing skips and the Anthropic client
passed 89 tests without skips. These results belong to the stream-fix checkpoint;
release staging of the subsequent version preparation remains separate.

The checked-in prompt-model JVM dump was stale. Investigation compared Kotlin
2.3.10 `AbiToolsV2` output, with all seven internal-API exclusions from the build
convention, for three independent inputs:

- The actual Maven Central `prompt-model-jvm:1.3.0-kroog.1` binary, verified
  against its published SHA-1 sidecar.
- The unchanged released source compiled during the regression run.
- The compiled stream fix.

All three generated dumps are byte-identical, with SHA-256
`077170abb02a48c754c3c8dbff2a0f5d58a2bd5fe3c07d7415cdfca3676fe521`.
They contain 344 public class blocks. Compared by class block, the old checked-in
dump has 308 unchanged blocks, 19 stale blocks, 17 missing blocks and no extra
blocks. Differences record already-published provider item identity, reasoning
replay, generated-file citations and streamed execution signatures. Block order
also differs. This candidate repairs only the prompt-model JVM baseline to match
the published binary, normalising the tool's extra blank line at EOF. It makes no
public API change and leaves Android and KLIB dumps untouched.
